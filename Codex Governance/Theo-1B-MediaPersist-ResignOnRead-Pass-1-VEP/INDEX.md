# Codex Governance Package — Theo 1B Chat Media Persistence: re-sign persisted images on read (Pass-1 Backend VEP)

- **Main artifact:** `Theo_1B_MediaPersist_ResignOnRead_VEP.md` — Pass-1 backend VEP (plan). Reviewer = Codex (Pass 2). Open it with the governance-bound GCR + Rule Anchor Table (Theo Grounding Conformance §3/§5; Golden Handler §2/§5.1/§5.3/§5.5).
- **Bug:** `theo_find_image` caches fetched (SerpAPI) images to our own Blob and returns a **60-minute read-SAS** URL; that exact URL is persisted in `theo_messages.media`. The blob is durable but the token expires, so after a hard refresh past the hour the reloaded chat's images render as **broken frames** (403); the lightbox breaks identically (same URL).
- **Fix (1 handler, `vaultgpt-func-premium`):** `theo_get_conversation` re-mints a **fresh read-SAS** on the reload read for each persisted image URL under `vaultgptstorage01/theo-content/images/<oid>/` (one shared user-delegation key per reload; mirrors the deployed `theo_find_image` shared-UDK idiom). Public URLs (Wikimedia/Commons, YouTube) pass through. Best-effort: a signing failure logs and returns the stored URLs — the read never fails.
- **Why this is small/safe:** premium's MI **already** mints user-delegation SAS against this exact account/container (the deployed `theo_create_attachment_upload`), so the SAS helpers are **reused byte-verbatim** (T12) — **no role grant, no new dependency**. The change is **additive** (one baseline line changed, `diff`-verified); `node -c` passes.
- **No** contract change (API Spec §2.1 `messages[].media` shape unchanged — only the SAS token is refreshed), **no** schema/migration (heals existing rows in place), **no** FE change, **no** `function.json` change, **no** `find_image` change.
